## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| State transition input | WheelState values passed to transition() must be valid enum members |
| SQL column values | state column must contain only valid WheelState.value strings |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-02-01 | Tampering | transition() bypass | mitigate | All state changes must go through transition() which validates against VALID_TRANSITIONS dict. No direct SQL UPDATE of state column allowed in callers. Enforced by Plan 02 wrapping transitions in transition_wheel_state() method. |
| T-02-02 | Tampering | SQL injection in schema | accept | Schema uses CREATE TABLE with hardcoded column definitions — no user input in DDL. Parameterized queries (?) for all data operations. Low risk: internal SQLite, no network exposure. |
| T-02-03 | Information Disclosure | Greek values in logs | accept | Greeks are non-sensitive financial data (delta, theta, etc.). No PII or credentials stored. Low risk. |
| T-02-04 | Tampering | Invalid option_type values | mitigate | option_type column constrained to "PUT" or "CALL" via application-level validation in open_wheel_position() (Plan 02). |
</threat_model>
