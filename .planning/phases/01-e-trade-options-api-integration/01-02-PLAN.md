<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| ETradeClient -> E*TRADE order API | Order parameters sent as JSON payload to external endpoint |
| E*TRADE API -> ETradeClient | Order confirmation and portfolio data received from external API |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-01-05 | Tampering | _build_options_order_request parameter injection | mitigate | All numeric params (strike_price, quantity, limit_price) are typed as float/int in Python — no raw string injection possible. The `str()` conversion in payload building is safe for numeric types. |
| T-01-06 | Elevation of Privilege | PreviewId replay across sessions | accept | E*TRADE enforces 3-minute window on PreviewIds server-side. Phase 1 does not cache PreviewIds — they are used immediately in test flows. Phase 3 will need to handle the Telegram approval delay (documented as known constraint in RESEARCH.md Pitfall 3). |
| T-01-07 | Denial of Service | clientOrderId collision causing duplicate rejection | mitigate | Use timestamp-based `f"OPTN_{get_et_now().strftime('%Y%m%d%H%M%S')}"` to ensure unique clientOrderId per request. In high-frequency scenarios (multiple orders within 1 second), this could collide — acceptable for wheel strategy which trades at most 1-2 times per week. |
| T-01-08 | Information Disclosure | Options position data logged | mitigate | Follow existing pattern: log only summary (action, symbol, quantity, price) not full API response. Do not log account_id_key in production logs. |
| T-01-09 | Tampering | Mock options position state manipulation | accept | Mock client is paper trading only. `_options_positions` dict is mutable by design. Same trust model as existing `self.positions` for equities. |
</threat_model>
